# Domain docs

How the engineering skills consume this repo's domain documentation.

## Before exploring, read these

- **`CONTEXT.md`** or **`GLOSSARY.md`** at the repo root: the domain vocabulary. Use its terms in code, issues and specs.
- **`docs/adr/`**: read the ADRs touching the area you work in.

If these files don't exist, proceed silently. The `/domain-modeling` skill creates them when a term or a decision is settled.

Product-wide specs live in `Gurren-Software/roadmap` > `specs/<product>/`. Read the spec linked from the Epic when a Task references one.
